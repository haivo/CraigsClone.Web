# M0.5 — Postgres in Docker

**Goal:** A Postgres the app can reach, plus a `docker compose up -d` for machines that don't have one.

## Decision made on the dev machine (2026-09-13)

The dev machine already runs a Postgres container, so it was reused instead of starting a second one:

| | |
|---|---|
| Container | `pg-simple-agent` (started with `docker run`, not compose) |
| Version | Postgres 16 |
| Host port | **5433** |
| User / password | `postgres` / `postgres` |
| Database for this project | `craigsclone`, created with `CREATE DATABASE craigsclone` |
| Other databases on it | `simple_agent` (another project, untouched) |

Because of that, three things differ from the original plan:

- The connection string uses **port 5433**, not 5432.
- Postgres is **16**, not 17. Test fixtures use `postgres:16` too, so tests match dev.
- `docker-compose.yml` is for **other machines**. It also uses port 5433 and Postgres 16, so a fresh clone works with the same connection string. Don't run it on the dev machine; 5433 is already taken.

**Steps**

1. Create the database in the existing container (already done on the dev machine):

   ```powershell
   docker exec pg-simple-agent psql -U postgres -c 'CREATE DATABASE craigsclone'
   ```

2. `docker-compose.yml` and `.env.example` in the repo root, as committed. Image `postgres:16`, port `${POSTGRES_PORT:-5433}:5432`, named volume, `pg_isready` healthcheck.

3. Validate the compose file without starting it: `docker compose config`.

**Files**

- `docker-compose.yml` (new)
- `.env.example` (new)

## Tests

Automated tests never use either the dev container or the compose file; they start their own throwaway `postgres:16` via Testcontainers.

**Unit** — none. YAML, not code.

**Integration** — none automated. `docker compose config` validates the YAML and prints the resolved file.

**End-to-end** — none automated. Manual check on the dev machine:

```powershell
docker exec pg-simple-agent psql -U postgres -d craigsclone -c 'select 1'
```

On a fresh machine: `docker compose up -d`, then `docker compose ps` shows `healthy`.

**Done when:** The `craigsclone` database answers `select 1`, and `docker compose config` prints without errors.

## Inspecting the database

There's no local `psql`. On the dev machine go through the container:

```powershell
docker exec pg-simple-agent psql -U postgres craigsclone
```

On a machine using compose: `docker compose exec db psql -U postgres craigsclone`. pgAdmin is also running on the dev machine at http://localhost:5050.
