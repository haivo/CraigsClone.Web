# M0.5 — Postgres in Docker

**Goal:** A `docker compose up -d` that starts Postgres 17 with data kept in a volume.

**Steps**

Create `docker-compose.yml` in the project root:

```yaml
services:
  db:
    image: postgres:17
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-postgres}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-postgres}
      POSTGRES_DB: ${POSTGRES_DB:-craigsclone}
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  pgdata:
```

Create `.env.example` (copy to `.env` to override the defaults):

```
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=craigsclone
```

Start it:

```powershell
docker compose up -d
docker compose ps
```

**Files**

- `docker-compose.yml` (new)
- `.env.example` (new)

## Tests

The compose file is for *your* dev database. Automated tests never use it; they start their own containers via Testcontainers, so they don't depend on this file at all.

**Unit** — none. It's YAML, not code.

**Integration** — none automated. `docker compose config` validates the YAML and prints the resolved file; treat that as the check.

**End-to-end** — none automated. Manual check: `docker compose ps` shows `healthy`, and `docker compose exec db psql -U postgres -c 'select 1'` prints 1.

**Done when:** `docker compose ps` shows the `db` service with status `healthy`.
