# M2.2 — ListingService (read side)

**Goal:** One class that holds all database queries for listings, so controllers stay thin and tests can target it directly.

**Steps**

Create `src/CraigsClone.Web/Services/IListingService.cs`:

```csharp
public interface IListingService
{
    Task<PagedResult<Listing>> BrowseAsync(int cityId, int categoryId, int page, int pageSize = 20);
    Task<Listing?> GetAsync(int id);
}
```

Create `src/CraigsClone.Web/Services/ListingService.cs` implementing it:

- `BrowseAsync`: filter by city and category, order by `CreatedAt` descending, count, then `Skip((page-1)*pageSize).Take(pageSize)`. If `page < 1`, treat it as 1. Return a `PagedResult<Listing>`.
- `GetAsync`: `Include(City)` and `Include(Category)`, then `FirstOrDefaultAsync`.

Register it in `Program.cs`:

```csharp
builder.Services.AddScoped<IListingService, ListingService>();
```

**Files**

- `src/CraigsClone.Web/Services/IListingService.cs` (new)
- `src/CraigsClone.Web/Services/ListingService.cs` (new)
- `src/CraigsClone.Web/Program.cs` (edited)

## Tests

**Unit** — none. Every method here runs a database query, so there is no logic to test without Postgres. (M4.2 later extracts pure helpers that do get unit tests.)

**Integration** — `Integration/Services/ListingServiceReadTests.cs`, `[Collection("postgres")]`. Insert your own rows with a unique title prefix into one city + category, then:

- 25 rows, page 1 → 20 items, `TotalCount == 25`, first item is the newest `CreatedAt`.
- page 2 → 5 items.
- page 0 and page -1 → same items as page 1.
- page 99 → 0 items, `TotalCount` still 25.
- Rows in a *different* category are not returned.
- `GetAsync(id)` returns the listing with `City` and `Category` populated (not null).
- `GetAsync(999999)` returns null.

**End-to-end** — none. No page calls the service until M2.4.

**Done when:** `dotnet build` passes and the integration tests are green.
