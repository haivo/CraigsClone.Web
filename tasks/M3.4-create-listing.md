# M3.4 — Post a new listing

**Goal:** `/post` shows a form. Submitting it creates the ad and redirects to its details page.

**Steps**

In `ListingsController`:

```csharp
[HttpGet("post")]
public async Task<IActionResult> Create(string? city)

[HttpPost("post")]
public async Task<IActionResult> Create(ListingFormVm form)
```

- GET: build an empty `ListingFormVm`, fill `Cities` and `Categories` select lists from the database. If `city` is given, preselect that city's id.
- POST: if `!ModelState.IsValid`, refill the select lists and return the view with the form. Otherwise call `CreateAsync`, set `TempData["Success"] = "Your ad is posted."`, and `RedirectToAction(nameof(Details), new { id })`.

Put the select-list filling in a private helper, because Edit needs it too.

Views:

- `Views/Shared/_ListingForm.cshtml` — a partial with `@model ListingFormVm` containing the fields: title, description (textarea), price, city (select), category (select), neighborhood, contact email, plus `<div asp-validation-summary="All"></div>` at the top and `<span asp-validation-for="...">` under each field. Give each input a `name` matching the property and an `id` (the tag helpers do this for you).
- `Views/Listings/Create.cshtml` — heading "post an ad", `<form method="post">`, the partial, and a submit button with text `post`.

## Tests

**Unit** — none new. The validation rules were unit-tested in M3.1 and the field copying in M3.2; the controller just connects them.

**Integration** — `Integration/Pages/CreatePageTests.cs`, `[Collection("app")]`:

- `GET /post` → 200, body contains `__RequestVerificationToken`, a `<select name="CityId">` with 6 options, and a `<select name="CategoryId">` with 22 options.
- `GET /post?city=austin` → the Austin option carries `selected`.
- `GET /post?city=nowhere` → 200 with nothing preselected (unknown city is ignored, not an error).

Posting with a valid token from `HttpClient` means scraping the token and cookie out of the GET response. That's fiddly and the browser test below covers it better, so leave the successful POST to E2E.

**End-to-end** — `E2E/PostListingTests.cs`, `[Collection("app")]`:

- **Happy path:** open `/post`, fill title (unique), description, price `25`, select `Austin`, select `furniture`, fill email, click `post`. Expect URL to match `/listing/\d+$`, the heading to equal the title, and `$25` to be visible. Then open `/austin/furniture` and expect the title to be visible.
- **Validation path:** open `/post`, fill only the description, click `post`. Expect URL still `/post`, expect text `The Title field is required` to be visible, and expect the description textarea to still contain what you typed.

**Done when:** Both E2E scenarios and the integration tests are green.
