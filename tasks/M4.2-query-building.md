# M4.2 — Query building in ListingService

**Goal:** Turn a `SearchFilterVm` into a database query: keyword, price range, sort, and paging.

**Steps**

In `ListingService`, add two public static helpers (static so they can be unit-tested without a database) and one instance method:

```csharp
// Escape LIKE wildcards so "50%" searches for a literal percent sign.
public static string EscapeLike(string s) =>
    s.Replace("\\", "\\\\").Replace("%", "\\%").Replace("_", "\\_");

public static IQueryable<Listing> ApplySort(IQueryable<Listing> q, ListingSort sort) => sort switch
{
    ListingSort.PriceAsc  => q.OrderBy(l => l.Price).ThenByDescending(l => l.CreatedAt),
    ListingSort.PriceDesc => q.OrderByDescending(l => l.Price).ThenByDescending(l => l.CreatedAt),
    _                     => q.OrderByDescending(l => l.CreatedAt),
};

public IQueryable<Listing> Query(IQueryable<Listing> source, SearchFilterVm f)
{
    var q = source;
    if (!string.IsNullOrWhiteSpace(f.Q))
    {
        var pattern = $"%{EscapeLike(f.Q.Trim())}%";
        q = q.Where(l => EF.Functions.ILike(l.Title, pattern, "\\")
                      || EF.Functions.ILike(l.Description, pattern, "\\"));
    }
    if (f.Min is not null) q = q.Where(l => l.Price >= f.Min);
    if (f.Max is not null) q = q.Where(l => l.Price <= f.Max);
    return ApplySort(q, f.Sort);
}
```

`ILike` is case-insensitive LIKE, Postgres only. Listings with `Price == null` naturally drop out when either bound is set, which is what users expect.

Then add a paging helper:

```csharp
public static async Task<PagedResult<T>> ToPagedAsync<T>(IQueryable<T> q, int page, int pageSize = 20)
{
    page = Math.Max(1, page);
    pageSize = Math.Clamp(pageSize, 1, 100);
    var total = await q.CountAsync();
    var items = await q.Skip((page - 1) * pageSize).Take(pageSize).ToListAsync();
    return new() { Items = items, Page = page, PageSize = pageSize, TotalCount = total };
}
```

Change `BrowseAsync` from M2.2 to accept a `SearchFilterVm` and use `Query` then `ToPagedAsync`.

## Tests

**Unit** — `Unit/Services/ListingServiceHelpersTests.cs`:

- `EscapeLike("50%")` → `50\%`; `EscapeLike("a_b")` → `a\_b`; `EscapeLike("a\\b")` → `a\\\\b`; `EscapeLike("plain")` → unchanged.
- `ApplySort` on an in-memory `List<Listing>.AsQueryable()` with three items: `Newest` puts the latest `CreatedAt` first; `PriceAsc` puts the cheapest first; `PriceDesc` the dearest first; two equal prices fall back to newest first.

**Integration** — `Integration/Services/ListingServiceQueryTests.cs`, `[Collection("postgres")]`. Each test inserts its own rows with a unique prefix and queries with `Q = prefix + " ..."` or filters scoped to its own city/category:

- keyword matches title; keyword matches description
- keyword is case-insensitive (`CHAIR` finds `chair`)
- a `%` in the keyword is literal: searching `50%` does not match `500`
- min only; max only; min and max together
- a listing with null price is excluded when min or max is set, and included when neither is
- `PriceAsc` and `PriceDesc` return rows in price order; `Newest` in `CreatedAt` order
- page 0 and page -1 behave like page 1
- a page past the end returns no items but the right `TotalCount`
- 20 rows → `TotalPages == 1`; 21 rows → 2
- `pageSize = 1000` is clamped to 100

**End-to-end** — none. M4.5 tests these through the browser.

## Note from the implementation

Both price sorts start with `OrderBy(l => l.Price == null)` before the price key. Postgres puts NULLs **first** on a descending sort, so without it "price: high to low" would lead with every "price not listed" ad. The extra key puts unpriced ads last in both directions, in Postgres and in the in-memory unit test alike. Pinned by `Sorts_OrderCorrectly_UnpricedLastForPriceSorts`.
