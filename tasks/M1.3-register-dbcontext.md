# M1.3 — Register the DbContext

**Goal:** Tell the app to create an `AppDbContext` connected to Postgres whenever something asks for one.

**Steps**

In `src/CraigsClone.Web/Program.cs`, after `var builder = WebApplication.CreateBuilder(args);` add:

```csharp
builder.Services.AddDbContext<AppDbContext>(o =>
    o.UseNpgsql(builder.Configuration.GetConnectionString("Default")));
```

Add the usings at the top:

```csharp
using CraigsClone.Web.Data;
using Microsoft.EntityFrameworkCore;
```

**Files**

- `src/CraigsClone.Web/Program.cs` (edited)

## Tests

**Unit** — none. DI registration is wiring, not logic; the integration test below is the right level.

**Integration** — `Integration/StartupTests.cs`, `[Collection("app")]`:

```csharp
[Fact]
public async Task App_CanReachDatabase()
{
    using var scope = fixture.Services.CreateScope();
    var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    Assert.True(await db.Database.CanConnectAsync());
}
```

This proves three things at once: the context is registered, the connection string setting is read, and the app really talks to the Postgres the fixture started.

**End-to-end** — the existing `HomePageTests.HomePage_Loads` still passes. If the registration were wrong, the app would fail on startup and this test would fail first.

**Done when:** `dotnet run` starts without errors and the tests are green.
