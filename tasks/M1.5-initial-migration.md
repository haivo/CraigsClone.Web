# M1.5 — Create the first migration

**Goal:** Generate the C# file that describes how to create the tables.

**Steps**

Run from inside the web project folder so the migration lands in `Data/Migrations`:

```powershell
cd src/CraigsClone.Web
dotnet ef migrations add Initial -o Data/Migrations
cd ../..
```

Open the generated `Data/Migrations/<timestamp>_Initial.cs` and skim it. You should see three `CreateTable` calls (Cities, Categories, Listings), two unique indexes on `Slug`, and one index on `CityId, CategoryId, CreatedAt`.

Then update `Integration/PostgresFixture.cs`: replace `EnsureCreatedAsync()` with

```csharp
await db.Database.MigrateAsync();
await DbSeeder.SeedAsync(db);
```

From now on, integration tests run against a schema created the same way production would be, and cities/categories are always present.

## Tests

**Unit** — `Unit/Data/MigrationTests.cs`: the most useful EF test there is, and it needs no database.

```csharp
[Fact]
public void Model_HasNoPendingChanges()
{
    using var db = new AppDbContext(new DbContextOptionsBuilder<AppDbContext>()
        .UseNpgsql("Host=unused").Options);
    Assert.False(db.Database.HasPendingModelChanges());
}
```

It fails whenever someone edits an entity or `OnModelCreating` and forgets to add a migration.

**Integration** — `Integration/Data/MigrationTests.cs`, `[Collection("postgres")]`:

- `GetAppliedMigrationsAsync()` contains an entry ending in `_Initial`.
- `GetPendingMigrationsAsync()` is empty.

**End-to-end** — none until M1.6 applies migrations on startup.

**Done when:** The three generated files exist and all tests above are green.
