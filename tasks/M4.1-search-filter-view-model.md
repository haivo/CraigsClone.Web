# M4.1 — SearchFilterVm and ListingSort

**Goal:** A class that the query string (`?q=bike&min=10&sort=priceasc&page=2`) binds into, plus a helper that turns it back into a query string for pager links.

**Steps**

Create `src/CraigsClone.Web/ViewModels/ListingSort.cs`:

```csharp
public enum ListingSort { Newest, PriceAsc, PriceDesc }
```

Create `src/CraigsClone.Web/ViewModels/SearchFilterVm.cs`:

```csharp
public class SearchFilterVm
{
    public string? Q { get; set; }
    public decimal? Min { get; set; }
    public decimal? Max { get; set; }
    public ListingSort Sort { get; set; } = ListingSort.Newest;
    public int Page { get; set; } = 1;

    // Only used by /search (M4.6). Null on a category page.
    public string? City { get; set; }
    public string? Category { get; set; }

    public Dictionary<string, string?> ToRouteValues(int? page = null)
    {
        var d = new Dictionary<string, string?>();
        if (!string.IsNullOrWhiteSpace(Q)) d["q"] = Q;
        if (Min is not null) d["min"] = Min.ToString();
        if (Max is not null) d["max"] = Max.ToString();
        if (Sort != ListingSort.Newest) d["sort"] = Sort.ToString().ToLowerInvariant();
        if (City is not null) d["city"] = City;
        if (Category is not null) d["category"] = Category;
        var p = page ?? Page;
        if (p > 1) d["page"] = p.ToString();
        return d;
    }
}
```

`ToRouteValues` leaves out empty values so links stay short, like `?q=bike&page=2` rather than `?q=bike&min=&max=&sort=newest&page=2`.

Sort values in the URL are `newest`, `priceasc`, `pricedesc`. Enum binding is case-insensitive, so these bind directly.

## Tests

**Unit** — `Unit/ViewModels/SearchFilterVmTests.cs`, all on `ToRouteValues`:

- default filter → empty dictionary
- `Q = "bike"` → only `q`
- `Q = "   "` → no `q` (whitespace is ignored)
- `Sort = Newest` → no `sort`; `Sort = PriceAsc` → `sort = "priceasc"`
- `Page = 1` → no `page`; `Page = 3` → `page = "3"`; `ToRouteValues(page: 2)` overrides `Page`
- `Min = 10.5m` → `min = "10.5"`

**Integration** — `Integration/Pages/FilterBindingTests.cs`, `[Collection("app")]`. Model binding is framework behaviour, so prove it with a real request once M4.5 wires the filter in:

- `GET /austin/furniture?sort=PRICEASC` → 200 (case-insensitive enum binding works).
- `GET /austin/furniture?sort=banana` → 200 and the page renders with newest-first (invalid sort falls back to default rather than erroring). If you'd rather it be a 400, pin that instead; just decide.
- `GET /austin/furniture?page=abc` → 200, treated as page 1.

**End-to-end** — none. Nothing user-visible until M4.4 and M4.5.
