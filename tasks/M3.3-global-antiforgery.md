# M3.3 — Anti-forgery on every POST

**Goal:** Every POST form is checked for the anti-forgery token automatically. You never need to remember an attribute per action.

**Steps**

In `Program.cs`, change the MVC registration to:

```csharp
builder.Services.AddControllersWithViews(o =>
    o.Filters.Add(new Microsoft.AspNetCore.Mvc.AutoValidateAntiforgeryTokenAttribute()));
```

Razor's `<form method="post">` tag helper adds the hidden token for you, so forms keep working.

**Files**

- `src/CraigsClone.Web/Program.cs` (edited)

## Tests

**Unit** — none. It is one line of framework configuration; only a real request can prove it.

**Integration** — `Integration/Pages/AntiforgeryTests.cs`, `[Collection("app")]`. These need the POST endpoints from M3.4 to M3.6 to exist. Write them now with `[Fact(Skip = "Route arrives in M3.x")]` so the suite stays green, and remove each Skip in the task that adds its route:

- `POST /post` with a valid-looking form body but **no** token → 400.
- `POST /listing/1/edit` with no token → 400.
- `POST /listing/1/delete` with no token → 400.

Note it must be 400, not 404: the filter runs before the action, so even a missing listing id gets rejected for the token first.

**End-to-end** — covered by M3.4's E2E test. A browser submitting the real form carries the token, so if that test passes, the filter is letting legitimate posts through.

**Done when:** The three integration tests return 400 and the site's own forms still work.
