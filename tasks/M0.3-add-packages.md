# M0.3 — Add NuGet packages

**Goal:** Pull in Entity Framework for Postgres, and the test helper that starts a throwaway Postgres in Docker.

**Steps**

```powershell
dotnet add src/CraigsClone.Web package Npgsql.EntityFrameworkCore.PostgreSQL
dotnet add src/CraigsClone.Web package Microsoft.EntityFrameworkCore.Design
dotnet add tests/CraigsClone.Tests package Testcontainers.PostgreSql
dotnet restore
```

What each package is for:

- `Npgsql.EntityFrameworkCore.PostgreSQL` — lets EF Core talk to Postgres.
- `Microsoft.EntityFrameworkCore.Design` — needed by the `dotnet ef` tool to create migrations.
- `Testcontainers.PostgreSql` — starts a temporary Postgres container during tests (see [01-testing-approach.md](01-testing-approach.md)).
- `Microsoft.EntityFrameworkCore` (tests, added in M1.2) — pinned to the same version as the Design package. Without it the test project gets an older EF Core through Npgsql and fails to compile against the web project. The Design package is `PrivateAssets`, so it doesn't flow across the project reference.

**Files**

- `src/CraigsClone.Web/CraigsClone.Web.csproj` (edited)
- `tests/CraigsClone.Tests/CraigsClone.Tests.csproj` (edited)

## Tests

**Unit** — none. Adding a package changes no logic.

**Integration** — M0.8's `PostgresFixtureTests` is the test for this task: it can only pass if `Testcontainers.PostgreSql` restored correctly and Docker is reachable.

**End-to-end** — none. Nothing user-visible changed.

**Done when:** `dotnet restore` succeeds and the csproj files list the packages.
