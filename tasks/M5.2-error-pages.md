# M5.2 — Friendly 404 and error pages

**Goal:** A wrong URL shows "page not found" in the site layout instead of a blank page. An exception shows a plain "something went wrong".

**Steps**

Create `Controllers/ErrorController.cs`:

```csharp
public class ErrorController : Controller
{
    [HttpGet("error")]
    public IActionResult Index() => View();

    [HttpGet("error/{code:int}")]
    public IActionResult Code(int code) => code == 404 ? View("NotFound") : View("Index");
}
```

Views `Views/Error/Index.cshtml` (`something went wrong, try again`) and `Views/Error/NotFound.cshtml` (`that page doesn't exist`, with a link home).

In `Program.cs`, replace the template's error handling with:

```csharp
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/error");
}
app.UseStatusCodePagesWithReExecute("/error/{0}");
```

`ReExecute` keeps the original URL in the address bar and renders the error view for it. The developer exception page still shows in Development.

## Tests

**Unit** — `Unit/Controllers/ErrorControllerTests.cs`. This controller has no dependencies, so it's a real unit test:

- `Code(404)` returns a `ViewResult` with `ViewName == "NotFound"`.
- `Code(500)` returns a `ViewResult` with `ViewName == "Index"`.
- `Index()` returns a `ViewResult`.

**Integration** — `Integration/Pages/ErrorPagesTests.cs`, `[Collection("app")]`:

- `GET /nowhere/nothing` → status 404 **and** body contains `that page doesn't exist` **and** contains `<header>` (it's inside the layout, not a bare response).
- `GET /listing/999999` → same.
- `GET /error/404` → 200 with the not-found text (direct hit works too).

**End-to-end** — `E2E/ErrorPagesTests.cs`, `[Collection("app")]`:

- Open `/nowhere/nothing`, expect the not-found text visible, click the home link, expect URL `/`.

**Done when:** Tests above are green.

## Note from the implementation

The error actions use `[Route(...)]`, not `[HttpGet(...)]`, and the controller carries `[IgnoreAntiforgeryToken]`. Reason: `UseStatusCodePagesWithReExecute` replays the *original* request against `/error/{code}`. When the original was a POST rejected by the anti-forgery filter (400, empty body), the replay is still a POST. With GET-only routes it answered 405 and overwrote the 400, which broke the M3.3 tests; and without the ignore attribute the global filter would reject the replay a second time. A `ViewResult` never sets a status code, so the original one survives the replay.
