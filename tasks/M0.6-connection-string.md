# M0.6 — Connection string

**Goal:** Tell the app how to reach the database.

**Steps**

In `src/CraigsClone.Web/appsettings.Development.json` add:

```json
"ConnectionStrings": {
  "Default": "Host=localhost;Port=5433;Database=craigsclone;Username=postgres;Password=postgres"
}
```

Port 5433, not the Postgres default of 5432: the dev machine's existing container listens there, and `docker-compose.yml` maps the same port so a fresh machine needs no edits. See M0.5.

Leave `appsettings.json` without a connection string. Anyone who needs a different value can set the environment variable `ConnectionStrings__Default` (two underscores), which overrides the file.

**Files**

- `src/CraigsClone.Web/appsettings.Development.json` (edited)

## Tests

**Unit** — none. Configuration, not logic.

**Integration** — `Integration/ConfigurationTests.cs`, `[Collection("app")]` (after M0.8): resolve `IConfiguration` from `fixture.Services` and assert `GetConnectionString("Default")` is not empty and contains `Host=`. This proves the override mechanism works, because the fixture replaces the value with the Testcontainers one.

**End-to-end** — none. Nothing user-visible until M1.6, whose E2E check (home page loads with a database) covers this.

**Done when:** The JSON is valid and the app still starts with `dotnet run --project src/CraigsClone.Web`.
