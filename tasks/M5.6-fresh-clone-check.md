# M5.6 — Fresh-clone check

**Goal:** Prove the README is true by following it from scratch.

**Steps**

```powershell
git clone C:\Data\sources\CraigsClone C:\Temp\craigsclone-check
cd C:\Temp\craigsclone-check
docker compose up -d
dotnet run --project src/CraigsClone.Web
```

In the browser: home → city → category → an ad → post a new ad → edit it → search for it → delete it.

Then run the test suite in the clone, exactly as the README says.

Clean up:

```powershell
docker compose down -v
cd ..
Remove-Item -Recurse -Force C:\Temp\craigsclone-check
```

If any step needed something the README didn't say, fix the README (M5.5) and repeat.

**Files:** none, unless the README needs a fix.

## Tests

This task *is* the manual end-to-end test of the whole project. The automated suite runs inside it.

**Unit** — in the clone: `.\test.ps1 unit` is green.

**Integration** — in the clone: `.\test.ps1 integration` is green. This proves the tests don't depend on anything on your original machine, such as a leftover container or database.

**End-to-end** — in the clone: `.\test.ps1 e2e` is green after the one-time Playwright install the README describes. Plus the manual click-through above.

**Done when:** Every step works without you touching anything outside the README. This is the v1 finish line.

## Note from the implementation

On the dev machine the check can't use the README's port 5433 (the dev container is there), so it sets `POSTGRES_PORT` in `.env` and `ConnectionStrings__Default` to a spare port. The first attempt used 5434 and failed with "password authentication failed": a native Windows service, "PostgreSQL Server 16", was already listening on 5434, Docker mapped the container to the same port without complaint, and the app reached the wrong server. The check script now picks the first free port from 5435 up. The README gained a troubleshooting line for this symptom, which is exactly the kind of thing a fresh-clone check exists to find.
