# M3.1 — ListingFormVm with validation

**Goal:** One class used by both the "post" and "edit" forms, with validation rules as attributes.

**Steps**

Create `src/CraigsClone.Web/ViewModels/ListingFormVm.cs`:

```csharp
using System.ComponentModel.DataAnnotations;
using Microsoft.AspNetCore.Mvc.Rendering;

namespace CraigsClone.Web.ViewModels;

public class ListingFormVm
{
    [Required, StringLength(120)]
    public string Title { get; set; } = "";

    [Required]
    public string Description { get; set; } = "";

    [Range(0, 99_999_999.99)]
    public decimal? Price { get; set; }

    [Required]
    public int? CityId { get; set; }

    [Required]
    public int? CategoryId { get; set; }

    [StringLength(80)]
    public string? Neighborhood { get; set; }

    [Required, EmailAddress, StringLength(254)]
    public string ContactEmail { get; set; } = "";

    // Filled by the controller, not posted by the form.
    public IEnumerable<SelectListItem> Cities { get; set; } = [];
    public IEnumerable<SelectListItem> Categories { get; set; } = [];
}
```

Why `int?` for CityId and CategoryId: with plain `int`, an empty dropdown posts 0 and `[Required]` never fires. With `int?`, an empty selection is null and validation catches it.

**Files**

- `src/CraigsClone.Web/ViewModels/ListingFormVm.cs` (new)

## Tests

**Unit** — `Unit/ViewModels/ListingFormVmTests.cs`. Validate with the same engine MVC uses, no web server needed:

```csharp
static List<ValidationResult> Validate(ListingFormVm vm)
{
    var results = new List<ValidationResult>();
    Validator.TryValidateObject(vm, new ValidationContext(vm), results, validateAllProperties: true);
    return results;
}
```

Start from a helper that returns a fully valid form, then break one field per test:

- valid form → no errors
- empty title → error on `Title`
- title of 121 characters → error on `Title`; 120 → no error
- `ContactEmail = "not-an-email"` → error on `ContactEmail`
- `Price = -1` → error on `Price`
- `Price = 100_000_000` → error on `Price`; `99_999_999.99` → no error
- `Price = null` → no error (optional)
- `CityId = null` → error on `CityId`
- neighborhood of 81 characters → error on `Neighborhood`; null → no error

**Integration** — none. The attributes are the whole behaviour; the unit tests exercise them exactly as MVC will.

**End-to-end** — none until the form exists (M3.4 tests that an invalid submission shows these messages in the browser).

**Done when:** `dotnet build` passes and the unit tests are green.
